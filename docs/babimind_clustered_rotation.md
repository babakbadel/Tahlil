# BabiMind — Clustered Rotation & Economic Velocity

## هدف

این لایه، مدل BabiMind را از مقایسهٔ چند دارایی به یک **Economic Causal/Rotation Graph** گسترش می‌دهد. عامل‌ها می‌توانند هزاران متغیر باشند، اما برای جلوگیری از نویز، ابتدا در خوشه‌های اقتصادی هم‌حرکت قرار می‌گیرند و سپس سرعت، شتاب، جریان پول و شکاف توجه آنها مقایسه می‌شود.

## اصول

- هم‌جهت بودن به معنی هم‌سرعت بودن نیست.
- رشد هم‌زمان چند دارایی می‌تواند ناشی از تزریق پول جدید باشد، نه Rotation صفرجمع.
- `velocity` تغییر متغیر در بازهٔ جاری است.
- `acceleration` تغییر velocity است.
- `leader` سریع‌ترین/قوی‌ترین عضو مشاهده‌شدهٔ خوشه است؛ این برچسب ادعای علت یا نیت نیست.
- `attention_gap = future_demand - attention` یک proxy برای شکاف بین اهمیت مورد انتظار و توجه فعلی است.
- مدل نباید از داده‌های قیمتی به‌تنهایی نتیجه بگیرد که «سرمایه‌دارها» یا بازیگران خاصی در حال خرید مخفیانه هستند؛ چنین نتیجه‌ای فقط با شواهد مستقل قابل بررسی است.

## امتیاز عامل

برای هر عامل:

`Score = direction + velocity + acceleration + flow + future_demand + supply_constraint + attention_gap + accumulation`

پیاده‌سازی فعلی وزن‌های اولیه و محافظه‌کارانه دارد و باید با backtest کالیبره شود؛ وزن‌ها «حقیقت اقتصادی» تلقی نمی‌شوند.

## امتیاز خوشه

برای هر خوشه، میانگین ویژگی‌های اعضا محاسبه می‌شود و یک `leader` و فهرست `followers` بر اساس رتبهٔ عامل‌ها تولید می‌شود.

این امکان را می‌دهد که BabiMind بگوید:

- کدام خوشه در حال شتاب گرفتن است؛
- رهبر فعلی خوشه چیست؛
- کدام اعضا عقب‌تر حرکت کرده‌اند؛
- آیا جریان پول با حرکت قیمت هم‌جهت است؛
- آیا تقاضای آینده با توجه فعلی فاصله دارد.

## زنجیره‌های علّی نمونه

`AI → Data Centers → Electricity → Grid → Copper → Mining Profit → Equities`

و یک مسیر ثانویه:

`Copper → Infrastructure Costs → Inflation Expectations → Gold`

این روابط باید در لایهٔ System Dynamics/Event Engine با داده و lag واقعی اعتبارسنجی شوند و صرفاً به‌عنوان فرض اولیهٔ شبکه استفاده شوند.

## استفادهٔ روزانه

در هر ران:

1. دادهٔ خام و timestamp ذخیره شود.
2. returns/flow/demand/supply/attention برای عامل‌ها ساخته شود.
3. عامل‌ها به cluster نگاشت شوند.
4. direction، velocity و acceleration محاسبه شوند.
5. cluster leaders و followers رتبه‌بندی شوند.
6. lead/lag با دادهٔ تاریخی سنجیده شود.
7. نتایج با ران قبلی مقایسه و وارد Model Memory شوند.
8. وزن‌ها و آستانه‌ها فقط پس از backtest به‌روزرسانی شوند.

## محدودیت مهم

این موتور یک **ranking/feature layer** است، نه موتور صدور سیگنال قطعی خرید و فروش. خروجی آن باید همراه با Market Data، Fundamental، Macro، Price Action، Options، Game Theory، Decision و Backtest وارد BabiMind شود.
